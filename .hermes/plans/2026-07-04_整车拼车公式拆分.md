# 整车 vs 拼车正算公式拆分 + 前端重构 实施方案

> **For Hermes:** Implement task-by-task, verifying each step.

**Goal:** 将正算公式拆分为整车（full_truck）和拼车（consolidated）两套独立公式，整车公式通过供应商真实运单反算标定，前端增加运输模式选择。

**Architecture:** 
- 整车正算：`cost = distance_km × base_rate × cargo_multiplier × (1+return) + toll + body_surcharge + misc`
- 拼车正算：维持现有 `distance + time + fuel + fixed` 分解
- 反算整车：只拟合 `base_rate` 每个车型（油价/时薪固定为 config 默认值），不需要 weight/volume
- 前端：先选模式 → 展现对应表单 → 计算

**Tech Stack:** FastAPI (Python 3.11), Next.js (React/TypeScript), OSRM routing

## Phase 1: 后端 - 整车正算公式独立

### Task 1.1: 整车成本聚合函数（费用计算公式.py）

在 `费用计算公式.py` 新增整车正算函数（不拆油耗/时间）：

```python
def 整车总成本(*, D_km, 基价每公里, 货物倍率, 空车返回, 
               路桥费_vnd, 车身附加费_vnd, 禁限行, 施工封闭, 上坡山区,
               装卸费_vnd, 保险费_vnd, 杂费_vnd) -> float:
    """整车一口价：距离×基价 + 所有附加费，不到处拆分油耗/时间"""
    return (
        距离成本(D_km, 基价每公里, 货物倍率, 空车返回)
        + 路桥费_vnd + 车身附加费_vnd + 禁限行 + 施工封闭 + 上坡山区
        + 装卸费_vnd + 保险费_vnd + 杂费_vnd
    )
```

### Task 1.2: cost_engine.py 整车模式走新公式

修改 `compute_cost_full_truck()`，不再调用 `_compute_for_model` 的完整拆解，
改用 Task 1.1 的 `整车总成本`。

CostBreakdown 中 time/fuel 相关字段填 0，distance_cost 填总价（扣掉 fixed 后的部分）。

### Task 1.3: API schema 调整 - 整车模式不需要 weight/volume

`QuoteRequest` 增加 `mode` 字段区分：
- `mode = "full_truck"`：`vehicle_model_id` 必填，`weight_kg` 可选（超载校验用），`volume_m3` 不需要
- `mode = "consolidated"`：`weight_kg` 和 `volume_m3` 必填，`vehicle_model_id` 忽略

### Task 1.4: API route 适配两种模式

`POST /api/v1/route/cost` 根据 `mode` 分发到不同计算函数。

## Phase 2: 后端 - 整车反算公式

### Task 2.1: calibration.py 整车模式只拟合 base_rate

`fit_rates()` 当 `mode == "full_truck"` 时：
- `fixed_fuel_price_vnd` 和 `fixed_wage_hourly_vnd` 强制从 config.py 取值（不可选 None）
- 未知数只有 `base_rate_vnd_per_km`（每种车型一个）
- `_design_row` 只填 distance_coef 列，跳过 time_coef 和 fuel_coef
- `base_rate = (actual_cost - fixed_known) / distance_coef`

输出格式不变，`wage_hourly_vnd` 和 `fuel_price_vnd` 直接输出 config 值（标注固定）。
