## 2. 交互模型

### 2.1 输入即上屏（乐观 UI）
- 用户发送后**立即**把消息上屏（输入框清空），AI 回复流式打字机
- 输入栏固定在底部，随滚动始终可见（与现有官网 AI 聊天 FAB 区分：这是主入口，不是角落助手）

### 2.2 方案卡 = 结构化工件（AI 回复的"实体"）
- AI 的最终回复不是纯文本，而是**结构化方案卡**：`{vehicles[], loading, cost, actions[]}`
- 卡片内三个区块：装载方案（车型/车数/装载率/重心/超重）· 3D 展开区 · 费用明细
- 卡片可整体复制/导出（装箱单 CSV + 报价单 PDF/Excel）

### 2.3 3D 展开（手风琴 → 完整工作台两级）
- 卡片内「▸ 展开 3D 装车图」：手风琴内嵌**小视口**（只读渲染 placements，拖拽只做旋转/缩放）
- 「打开完整 3D 工作台」：新 tab 跳 `/tools/loader?vehicle=40hq`，adapter 收 placements 后进入可编辑态（二期：postMessage 直传，`{truck, placements}`）
- 交互闭环：小视口看图 → 工作台细调 → 回对话继续改

**3D 双路径契约（@codex-03 审查①的落地，写进 adapter 设计）：**
- **读模式（只读小视口/方案卡图）**：adapter 用**原始写入**渲染 AI placements——直接写 `Planner.placements` + `fire('placement')`，**跳过** `centeredPlacement`/`centerOnSupport`/推挤/沉降等一切变换 → 保证「AI 方案卡布局 = 3D 渲染布局」逐件坐标一致（守验收标准 2）
- **写模式（完整工作台，可编辑）**：才走正常交互（拖拽/推挤/对齐会合法变换坐标）
- **回写闭环**：用户在完整工作台改完 → 返回对话时，adapter 把**最终坐标**回写方案卡（新对话轮次卡片刷新，展示真实落位）→ 用户看到、导出、下订单的都是最终坐标，AI 方案卡永不撒谎

### 2.4 追问闭环（方案卡上的编辑是"对话"不是"表单"）
| 用户说 | 系统动作 |
|---|---|
| "换 17.5 平板试试" | 方案卡车型 chip 高亮切换 → 重跑装载+报价 → 卡片原位刷新（打字机差分） |
| "再加 50 箱" | 货物清单 chip +50 → 重算 → 装载率/车数可能变 |
| "改到胡志明" | 路线重算 → 费用明细更新 |
| "太贵了，有便宜方案吗" | suggest_vehicles 按价格排序 → 多方案对比条 |

- 原则：**每次修改 = 一次新对话轮次**，上一条方案卡保留（可回看/对比），不是原地覆盖抹历史
- 货物清单是全局状态（页面顶部常驻「当前货物」chip 条，任何轮次可见可改）

### 2.5 空态 = 引导（新客户 30 秒上手）
- 欢迎卡：一句话说明「说人话，系统帮你算装车和运费」
- 4 个示例按钮（对应场景 A/B/C/D），点击自动填入输入栏

## 3. 视觉规则（沿用品牌 token）

- 方案卡：白底圆角 14px + 顶部 3px 青蓝渐变线（与首页双卡同语言）；装载率进度条复用语义色（>85% 绿 / 70-85% 橙 / <70% 灰，与 Carbox 一致）
- AI 消息气泡：左对齐（助手）/ 右对齐（用户），品牌 50 号浅蓝底 + 深蓝文字
- 3D 小视口：深色嵌入块（navy-950 底），与 Carbox 场景一致
- 三语：壳层 i18n；方案卡内容双语规则见 §5 建议

## 4. 通用性设计（脱离玖能专属）

- 文案层用「货运/装载/方案」中性词，不出现玖能专属话术
- 车型/边关费/汇率/税率/模板全部走配置（现有架构已支持）
- 方案导出模板：装箱单 + 报价单（可换 logo/公司名）→ 即「白标」可交付任何货运公司
- 「常用货物模板库」（托盘/纸箱/桶/设备等）内置 + 用户自定义持久化
