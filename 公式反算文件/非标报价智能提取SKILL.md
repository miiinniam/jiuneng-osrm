# 非标报价智能提取（AI 驱动，通用 Skill）

> 本文档面向任何具备多模态视觉能力的编码 Agent（Claude / Hermes / 多模态 LLM）。
> 不依赖固定模板、正则表达式或 OCR 引擎——核心能力来自 AI 自身对图片/表格/文本的理解。
>
> **定位**：这是流水线的"第零阶段"——在 [`报价数据提取SKILL.md`](./报价数据提取SKILL.md)
> （第一阶段：结构化提取）之前，先把"没有标准格式的原始报价"变成"能被识别出结构的数据"。
>
> **互联文档**：
> - 结构化报价提取 → [`报价数据提取SKILL.md`](./报价数据提取SKILL.md)（当原始文件有清晰行列结构时直接用那个）
> - 反推市场费率 → [`运费反算SKILL.md`](./运费反算SKILL.md)
> - 校准部署 → 项目根 [`SKILL.md`](../SKILL.md)

---

## 1. 这个 skill 解决什么问题

供应商报价的来源远比 Excel 复杂：

| 来源类型 | 例子 | 难点 |
|----------|------|------|
| **聊天截图** | Zalo/微信供应商发来的报价截图 | 混有对话气泡、emoji、越南语口语 |
| **照片** | 纸面报价单用手机拍的 | 倾斜、阴影、手写修改 |
| **非标准表格** | 合并单元格、多层表头、横向/纵向混合布局 | openpyxl 读到的是碎片，需要语义重组 |
| **邮件正文** | 供应商直接在邮件里列了几行价格 | 没有行列概念，只是纯文本列表 |
| **多来源混排** | 一张图里既有表格又有备注文字 | 需要区分"数据区"和"说明区" |
| **PDF 扫描件** | 没有文字层，只有一个图片 | Tesseract 无法处理越南语特殊字符 |

**本质差异**：`报价数据提取SKILL.md` 假设"文件里有规整的表格"，用程序读行列即可。
**本 skill** 假设"文件里有什么完全不知道"，靠 AI 的眼睛和大脑去理解内容、定位数据、提取字段。

## 2. 核心思路：AI 四步法

```
原始文件 (PNG/JPG/PDF/Excel/Text)
    ↓
步骤 1: 全量读取 → 把文件内容"喂"给 AI 看
    ↓
步骤 2: 语义识别 → AI 自己找出：哪里是数据？列名是什么？单位是什么？
    ↓
步骤 3: 字段映射 → 把识别出的列映射到标准样本 JSON 的字段
    ↓
步骤 4: 输出校验 → 自动检查输出 JSON 的完整性，标记不确定的字段
```

### 2.1 步骤 1：全量读取

根据文件类型选择读取方式：

| 文件类型 | 读取方式 | 工具 |
|----------|----------|------|
| **图片** (PNG/JPG) | 直接让 AI 看图，不做 OCR 预处理 | 多模态模型的 vision 能力 |
| **Excel** (.xlsx/.xls) | 先用 openpyxl 读出行列数据（含合并单元格信息），再把整个数据矩阵喂给 AI | Python openpyxl |
| **PDF** | 先用 PyMuPDF/marker-pdf 提取文本+图片，再把提取结果喂给 AI | PyMuPDF / marker-pdf |
| **纯文本** (邮件/聊天记录) | 直接把全文喂给 AI | 直接粘贴 |

**关键原则**：不要自己预处理——把最原始的内容给 AI 看。AI 比 OCR 更擅长理解上下文（比如区分"1,600,000"是价格还是电话号码）。

### 2.2 步骤 2：语义识别

**告诉 AI 要回答以下问题**（用 prompt 引导）：

```
请分析这份供应商报价文件，回答以下问题：

1. 这是一份什么类型的文件？（报价费率表 / 逐单结算记录 / 合同附件 / 聊天报价 / 其他）
2. 报价方是谁？（公司名、地址）
3. 报价基准是什么？（整车/拼货；按吨位/按车型/按路线/按体积/按CBM）
4. 数据区在哪里？（描述行列结构：表头在第几行、数据从第几行开始、有哪些列）
5. 每一列代表什么？（列名、单位、数据类型）
6. 有没有页脚说明？（如"不含VAT"、"走XX口岸加收XX"、"报价有效期"）
7. 金额单位是什么？（VND/USD/RMB/CNY）
8. 有没有隐含信息？（比如公司名里暗示了起点地址、车型列名里暗示了吨位）
```

### 2.3 步骤 3：字段映射

把 AI 识别出的每一行数据，映射到标准样本 JSON 字段（详见 [`报价数据提取SKILL.md` §3](./报价数据提取SKILL.md)）：

| 识别出的列/信息 | 映射到标准字段 | 映射规则 |
|----------------|----------------|----------|
| 目的地/收货地 | `dest_address` | 补全 "Việt Nam" 后缀 |
| 发货地/公司地址 | `origin_address` | 从信头/公司名提取 |
| 车型/吨位列 | `vehicle_model_id` + `weight_kg` | 先提取吨位数字，再查 `车辆型号库.csv` 映射（见 §4） |
| 报价金额 | `actual_cost_vnd` | 注意单位（千/百万/万），统一转成 VND 数值 |
| 报价模式 | `loading_mode` | 见 §4.5 判断逻辑 |
| 重量/体积 | `weight_kg` / `volume_m3` | 报价单没给重量时按 §5 优先级假设 |
| 备注/脚注 | `notes` | 原样保留 + 标注"AI 识别，需人工核对" |
| 距离/时长（如报价单自带） | `source_distance_km` / `source_duration_h` | 仅作参考，下游反算用 OSRM 重算 |

### 2.4 步骤 4：输出校验

生成 `samples_<供应商名>.json` 后，自动检查：

- [ ] 每条样本都有 `origin_address` 或 `origin` 坐标
- [ ] 每条样本都有 `dest_address` 或 `destination` 坐标
- [ ] 每条样本都有 `actual_cost_vnd`（正整数）
- [ ] `loading_mode` 只能是 `full_truck` 或 `consolidated`
- [ ] `vehicle_model_id` 必须在 `车辆型号库.csv` 中存在（`full_truck` 模式）
- [ ] 没有两个样本完全相同（起点+终点+车型+重量都一样 → 可能是重复提取）
- [ ] `notes` 里标注了"AI 提取，需人工核对"以及来源文件和不确定项

## 3. 实际操作步骤（Agent 执行指南）

### 3.1 对于图片文件

```
1. 用多模态 vision 能力直接读图（不要跑 OCR）
2. 用 §2.2 的 prompt 让 AI 分析图片内容
3. 让 AI 直接输出表格数据（逐行列出：目的地 | 车型吨位 | 价格）
4. 按 §2.3 映射字段，生成样本 JSON
5. 地理编码所有唯一地址（缓存复用），填入经纬度
```

**示例 prompt（给 AI 的）**：

```
你是一份越南供应商报价单的图片。请仔细阅读图片中的所有文字和数字，
按以下格式输出你看到的所有报价数据：

每行一条，格式：
目的地 | 车型/吨位 | 报价金额(VND) | 备注

然后回答：
- 报价方公司名和地址是什么？
- 这是整车报价还是拼货报价？
- 报价含税吗？有什么附加条件？
- 有没有脚注文字（页底的说明）？
```

### 3.2 对于非标准 Excel

当 openpyxl 读出来的数据无法被 `报价数据提取SKILL.md` 的固定算法识别时（合并单元格、多层表头、非矩阵布局）：

```
1. 用 openpyxl 读取全部行列数据（保留空单元格和合并单元格信息）
2. 把原始行列矩阵（含坐标）全部打印出来喂给 AI
3. 让 AI 在"看到"整个数据矩阵后，标出数据区的起止行列
4. 让 AI 重新解释每一列的含义
5. 按 §2.3 映射字段
```

### 3.3 对于聊天截图/邮件正文

聊天报价的典型形态：
```
供应商: 北江→河内 5T车 3tr2，10T 4tr5
你: 含税吗？
供应商: chua VAT em oi. Rẻ nhất rồi đó 😅
```

处理方式：
1. 把所有聊天文本直接喂给 AI（对话上下文有助于理解价格单位/条件）
2. 让 AI 从对话中提取：起点、终点、车型吨位、价格、是否含税
3. 对话中隐含的条件（"不含税"、"最便宜了"、"走友谊关"）写进 `notes`
4. 对话中可能有多个报价（不同车型/不同路线），每行一条样本

## 4. 车型-吨位映射（引用现有体系）

提取出的"车型描述"（如 "XE 5T"、"3 CHAN"、"15 tấn"、"container 40"）需要映射到
`车辆型号库.csv` 中具体的 `model_id`。映射规则与 [`报价数据提取SKILL.md` §5](./报价数据提取SKILL.md)
完全一致：

1. 按报价描述判断车身大类 → CSV 的 `category` 列
2. 在该 `category` 内找 `max_load_ton` ≥ 目标吨位且最接近的型号
3. 取该行的 `model_id` 填入样本

**新增：AI 辅助映射**

当报价描述的车型无法明确归类时（比如 "xe tải nhẹ" 轻卡是 small_box 还是 high_side？），
让 AI 根据越南语语义判断：

- "xe tải" / "xe ben" → 通常是 flatbed（平板/翻斗）
- "xe thùng" / "xe mui" → 通常是 high_side（高栏/箱体）
- "container" / "cont" → container
- "xe lạnh" / "xe đông lạnh" → cold_chain
- "xe nhỏ" / "xe tải nhẹ" / "xe bao" → small_box（小厢货）

---

## 5. loading_mode 判断（引用现有体系）

与 [`报价数据提取SKILL.md` §4.5](./报价数据提取SKILL.md) 一致：

- 按吨位/车型去某目的地的整车价 → `full_truck`
- 按重量/体积/CBM 计费、写着 "ghép hàng" / "拼车" / "零担" → `consolidated`
- 不确定时默认 `full_truck`，标注"AI 判断，需人工核对"

**AI 辅助判断**：当报价单没有明确写模式时，AI 可以根据上下文推理：
- 报价单写"XE 5T đi Hà Nội: 3,400,000" → "一辆5吨车去河内" → 整车
- 报价单写"500đ/kg, tối thiểu 200kg" → "每公斤500盾，最低200公斤" → 拼货

## 6. 输出格式（与标准格式完全兼容）

输出的 `samples_<供应商名>.json` 格式与 [`报价数据提取SKILL.md` §3](./报价数据提取SKILL.md)
**完全一致**——这样才能无缝交给 `运费反算SKILL.md` 处理。

唯一的区别：每条样本的 `notes` 里必须加标注：

```
"notes": "AI提取自[文件名/图片来源]，<原有备注>。AI识别置信度：高/中/低。需人工核对：<不确定的字段>"
```

### 6.1 置信度标注

| 置信度 | 条件 | 处理建议 |
|--------|------|----------|
| **高** | 图片清晰、表格规整、所有数字可辨认、字段映射无歧义 | 可直接用于反算，人工抽查即可 |
| **中** | 图片略有模糊、部分字段需推断、车型映射有多个候选 | 建议人工核对后再用于反算 |
| **低** | 图片模糊、混有手写、语言混排导致理解不确定 | 必须人工核对，不直接用于反算 |

---

## 7. 已知的坑（参考 `报价数据提取SKILL.md` 的踩坑经验）

1. **地址要补"Việt Nam"后缀**：供应商写"Hà Nội"不写国家，地理编码可能定位到同名地点
2. **车型列名里的吨位优先于车型库吨位**：报价单写"XE 4.8T"就用 4800kg，不要用映射到的 `high_side_5t` 的 5000kg 覆盖
3. **同一起点多条样本时共用经纬度**：提取完先去重地址、统一地理编码，再套进所有样本
4. **经纬度必须嵌套对象**：`"origin": {"lat": ..., "lng": ...}`，不能扁平
5. **越南语数字格式**："."是千分位分隔符，"1.600.000" = 1,600,000
6. **越南语金额缩写**："3tr2" = 3,200,000 VND、"500k" = 500,000 VND
7. **页脚说明不自动套用**：写进 `notes` 让人工判断，不要自动加减价格
8. **报价不含税是常态**：越南供应商报价通常不含 VAT（10%），需要在 notes 里注明

```

```

**使用优先级**：
1. 如果原始文件打开就能看到规整的行列表格 → 直接用 `报价数据提取SKILL.md`

## 10. 局限性

- **AI 会产生幻觉**：对于模糊不清的数字（如图片里的 "8" vs "3"），AI 可能猜错。
  置信度标注 + 人工核对是必须的，不是可选的。
- **不替代人工判断**：AI 提取的数据在用于反算之前，至少需要人工抽查 30% 的样本。
- **越南语 OCR 不可靠**：不要用 Tesseract 直接 OCR 越南语图片——音调符号（ắ, ố, ệ）
  经常识别错误。用 AI 的 vision 能力直接读图，比 OCR→纠错更准。
- **复杂合并单元格**：如果 Excel 的合并单元格嵌套超过 3 层，可能需要在 openpyxl 读取后
  手动展开（写一个小脚本把合并区域的值填充到所有子单元格），再喂给 AI。
- **依赖 AI 模型的多模态能力**：本 skill 假设执行 Agent 具备读图能力。如果 Agent 不能读图，
  回退到 `报价数据提取SKILL.md` 的 Tesseract 方案（需要先安装 tesseract + vie 语言包）。
